# 구현 메모

## 구조

기존 화면 위에 여러 개의 연출 스크립트를 중첩하는 방식을 사용하지 않습니다. 각 게임은 `Overkill.register(id, factory)`로 자체 상태, 입력 처리, 업데이트, 그리기를 등록합니다. 공유되는 것은 화면 탐색, 입력 정리, 오디오 수명, 기록 저장, 결과 UI 같은 기반뿐입니다.

각 게임 팩토리가 반환하는 `state`는 검증 시 읽는 상태이며 별도의 치트 버튼이나 자동 정답 기능으로 노출하지 않습니다. 브라우저 개발자 도구로 소스를 볼 수 있는 완전한 로컬 게임이므로 보안이 필요한 경쟁 점수판용 구조는 아닙니다.

## 입력과 수명

마우스·터치는 Pointer Events와 포인터 캡처로 처리합니다. 키보드 입력은 텍스트 필드의 편집과 충돌하지 않도록 구분합니다. 버튼의 기본 Space/Enter 활성화도 유지합니다.

현재 세션의 이벤트는 AbortController에 묶습니다. 화면 이동 시 이벤트를 해제하고 rAF를 취소하며, 진행 예약 큐·입력 키·장식 파티클·오디오 소스를 정리합니다. 이전 화면을 닫았는데 타이머나 소리가 계속 남는 경로를 제거했습니다.

일시정지 중에는 게임 업데이트와 경과 시간이 멈추며, 별도로 열어 둔 이미지 처리·문서 조사 같은 부가 기능을 제외하고 게임 조작 패널도 잠깁니다. 다른 탭을 보는 동안에도 시간 진행을 멈춥니다.

실제 시간 측정은 프레임 간의 활성 경과 시간을 사용하고, 물리 계산의 프레임 단계는 최대 40ms로 제한합니다. 프레임 지연으로 물리 객체가 과도하게 튀는 것을 줄이면서 체감 시간 게임의 초 단위를 프레임 수에 묶지 않도록 분리했습니다.

## 판정

승패·점수는 해당 게임의 상태에서만 결정됩니다. 실패해도 무조건 성공 제목이 뜨는 별도 전역 연출 타이머는 없습니다.

- 주사위는 앞면 값, 최종 정착 값, 기록된 결과가 같은 값입니다. 점수는 눈의 크기가 아니라 별 충돌과 궤도 정착에서 나옵니다.
- 소나는 탐침에서 숨은 목표까지의 실제 유클리드 거리를 표시합니다.
- 노노그램은 고정 원본 좌표와의 완전 비교가 아니라 모든 행·열의 연속 길이를 검사합니다. 힌트를 만족하는 다른 해도 정답입니다.
- 숫자 미로는 소수를 버리지 않습니다. 0.5 연산도 그대로 보존합니다.
- 비트 복원은 참 양성뿐 아니라 잘못 추가한 스텝까지 반영합니다. 32칸을 모두 켜는 것으로 통과하지 못합니다.
- 파형 조율은 샘플 좌표 간 평균 제곱 오차에서 일치도를 구합니다. 임의의 성공 수치를 표시하지 않습니다.
- 이름의 해시 인덱스는 부호 없는 정수로 처리합니다. 기본값 `그림자_칼날_07`에서 배열 밖 인덱스가 생기지 않습니다.

## 자원 관리

동시에 살아 있는 게임 루프는 하나입니다. 화면에 있는 게임만 업데이트합니다. 파티클은 세션당 최대 240개, 궤적은 각 게임의 정해진 길이까지만 유지합니다. 시간여행의 기록은 최근 10초 범위입니다.

캔버스는 기기 배율 최대 2와 내부 1800×1200 상한을 적용합니다. LITE 모드는 배율 1과 더 적은 장식 파티클을 사용합니다. 게임 규칙은 바꾸지 않습니다.

오디오는 외부 음원 파일이 아니라 Web Audio 합성입니다. 재생 소스는 세션별 그룹으로 묶고, 정지·일시정지·화면 종료 시 그룹의 소스를 끕니다. 곡·가사·음원 샘플을 포함하지 않았습니다.

## 데이터와 파일

이미지 변환과 다운로드는 로컬 Blob을 사용합니다. 객체 URL은 사용 후 해제합니다. 이미지 처리가 끝나기 전에 다른 게임으로 이동한 경우 완료 콜백이 새 화면의 DOM을 바꾸지 않도록 세션 생존 여부와 요청 번호를 확인합니다.

API 호출, 외부 CDN, 분석 수집, 광고, 계정, 서버 데이터베이스는 없습니다. 기록 키는 `overkill-v2`입니다. 이 기록에는 점수·별·방문 수·성공 수·환경 설정만 저장하며 사용자의 이미지, 문서 내용, 생성한 비밀번호는 저장하지 않습니다.
